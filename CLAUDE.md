# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`eduparents` is a pixel-mockup of a parent-facing school app (Vietnamese UI, "EDU Parent"), rendered as a single Next.js page inside a fake iPhone frame. There is no backend, no router and no real data. The app lives in `web/`; a sibling project, **eduteachers**, is not in this repo and is only referenced in code comments as the pattern source.

The repo root also holds the original vanilla prototype (`index.html`, `scripts/app.js`, `styles/main.css`). It is the reference `web/` is being ported from. Screens not yet rebuilt in `web/` still exist only there.

`reference/` is the spec source: screenshots plus `prd.md`, `screens.md` and `flows.md`. Read them before building a screen that doesn't exist in `web/` yet. They are written in Vietnamese and describe only what appears in the screenshots.

## Commands

Run everything from `web/`. The lockfile is `pnpm-lock.yaml`. pnpm is not installed globally on every machine, so `npx pnpm@9 …` works. `.claude/launch.json` starts the dev server with `npm run dev` instead.

```bash
cd web
pnpm install --frozen-lockfile
pnpm dev                 # next dev -p 3100  → http://localhost:3100
pnpm build               # next build
npx tsc --noEmit         # the real type check
```

- `next.config.mjs` sets `typescript.ignoreBuildErrors: true`, so **`next build` does not type-check**. Run `npx tsc --noEmit` yourself.
- `pnpm lint` is broken: the script is `eslint .` but ESLint is not a dependency.
- There is no test runner and there are no tests.
- `web/.claude/settings.json` is a second, nested settings file, separate from the repo-root `.claude/settings.json`. Both deny `git commit` and `git push` for Claude.

## Architecture

**Navigation** is a single `useState<Screen>` switch in `web/app/page.tsx`, with no router library. The page also draws the phone chrome (`.device-frame`, status bar, `.screen-root`, `#overlay-root`).
- The app opens on the **ECO Me home** (`eco-me/eco-home-screen.tsx`): promo banner with greeting/search/bell, wallet card, 7 service tiles plus "Xem thêm" (`eco-services` = "Danh sách dịch vụ", 19 education services in the order of the real app), the student list and a bottom tab bar. "ECO School" (last tile of the list) opens the original ECO Phụ huynh Home (`home`, `ParentsHomeScreen`), which has a ‹ back to ECO Me. The service catalogue is `eco-me/services.ts` (icon key + gradient `tint`, drawn by `eco-me/service-icon.tsx` with lucide); only services with an `intent` (or `ecoParent`) are interactive, the rest (Học bạ số: its PRD page is empty) are muted placeholders. Nạp tiền and Chuyển tiền open the wallet flows (`topup-wallet/`, `transfer/`); Rút tiền, Mã thanh toán, search, the banner CTA and the bottom tabs are inert; the bell opens **Thông báo** (`notifications/`, data in `MOCK_NOTIFICATIONS`, tapping an item marks it read and deep-links via its `target`).
- Launching a student-scoped service goes through `shared/use-service-launcher.tsx` (`useServiceLauncher`, `eligibleStudents`): 2+ eligible students → picker sheet, exactly 1 → straight in. Use it for any new service entry point. Every screen receives one `ServiceNav` handler, `onOpenService(intent, studentId)`; `page.tsx` maps the intent to a screen through `INTENT_SCREEN`.
- `activeStudentId` is shared by every screen after Home.
- `returnScreen` stands in for the vanilla app's navigation stack (`App.back()`). Every service screen (Fee, Topup, Báo vắng, Bài tập, Kết quả học tập, Phiếu bé ngoan, Hóa đơn) can be entered from ECO Me home, the service list, ECO Phụ huynh Home or the Học sinh screen, and its back button returns to whichever it came from. Link student and Hướng dẫn use it too. Học sinh has its own `studentOrigin`, because features opened from it overwrite `returnScreen` with `'student'`.
- When adding a feature screen: add it to the `Screen` union and `INTENT_SCREEN` in `page.tsx`, add the intent to `ServiceIntent` (and `eligibleStudents` if gated), give it an `intent` in `eco-me/services.ts`, and add it to `PARENT_SERVICES` in `shared/parent-services.ts`: that one catalogue feeds both the ECO Phụ huynh Home grid and the Học sinh page (`shared/paged-icon-grid.tsx`, swipeable, 8 icons per page; Học sinh lists only the services `eligibleStudents` allows for that student).
- Deep links and shortcuts: `medicineOrderId`, `chatThreadId` and `absenceOnCreate` in `page.tsx` open Dặn thuốc on an order, Trao đổi on a conversation, Báo vắng on its create form. `subReturn` makes back return to the feature that opened a shortcut (Điểm danh → Báo vắng, Trao đổi → đơn) without overwriting `returnScreen`.

**Features** are self-contained folders under `web/components/parents/<feature>/`. Each has an `index.tsx` (`XxxApp`) that owns the feature's inner screen state and renders sub-screens such as `fee-lookup-screen.tsx` or `homework-submit-screen.tsx`. Many `index.tsx` files carry a comment naming the matching function in `scripts/app.js` (for example `App.startFee()`). Read that function when behaviour is unclear.

**Data** comes from `web/lib/mock-data.ts`, the single source of truth for types and mock data. It deliberately mirrors `STUDENTS` in `scripts/app.js`. Screens read from `MOCK_STUDENTS` and mutate it in place, so state persists until a page reload. Only 3 students exist, and feature gating depends on which one is selected:
- `vy`: mầm non, healthy z-score, `supportsTopUp`, no linked invoice.
- `khoa`: phổ thông, elevated z-score, has invoices, homework, absences and results.
- `lam`: mầm non, underweight z-score.

Gating helpers and flags are `isMamNonStudent` (checks whether `school` contains "Mầm non"), `supportsTopUp`, `hasLinkedInvoice` and `results: null`. Phiếu bé ngoan and Nhật ký chăm sóc are Mầm non only, and Nạp điểm is only for `supportsTopUp` students. Test any gated change against all three students.

**Overlays**: bottom sheets and dialogs must render through `shared/overlay-portal.tsx` (`OverlayPortal`). It portals into `#overlay-root`, a sibling of the scrollable `.screen-root`, and locks body scroll. An inline `.sheet` is `position:absolute` against `.screen-root`, so it scrolls away with the page. Use the existing `.scrim` / `.sheet` classes.

**Styling** is hand-written plain CSS in `web/app/globals.css` on top of the **ECO Design System** ("ECO Me DS"). Three files load in this order from `layout.tsx`: `ds-tokens.css` (every DS token as a CSS variable: `--text-*`, `--bg-*`, `--border-*`, `--space-*`, `--radius-4/8/12/20`, `--text-body-xs/s/m/l`, plus the SF Pro `@font-face` from `public/fonts/*.woff2`; the font stack is `-apple-system, BlinkMacSystemFont, 'SF Pro', 'Segoe UI', Roboto, …`: Apple devices use the system SF (same look as the reference deployment at edu-parents.vercel.app, whose SF Pro files never load), other platforms get the SF Pro webfont. The static SF Pro Text webfont renders about 4% wider than the system font, which looked too big), `eco-ds-bundle.css` (the DS component stylesheet, `.eco-*` classes; it is loaded but the app's screens do not use the DS React bundle) and `globals.css`. It does `@import 'tailwindcss'` and has Tailwind/shadcn deps, but screens do not use utility classes. The legacy `--c-*` names at the top of `globals.css` are aliases that now point at DS tokens (`--c-gray-150` = `--border-soft`, `--c-yellow` = `--eco-yellow`, `--c-navy` = `--text-label`, ...), so old rules render in DS colours; the vanilla app (`styles/main.css`) is no longer kept in sync and stays monochrome. The last block of `globals.css` ("ECO Design System skin") re-skins the shared classes (`.topbar`, `.btn`, `.tab-pill`, `.segmented`, `.badge`, `.sheet`, `.dialog-card`, `.field`, `.search-box`, `.student-header`, the icon grids) to the DS look; add DS-wide changes there. Rules: yellow `--eco-yellow` is the primary action (`.btn-primary`, DS Button `brand`), blue `--text-link` is links and selection, `--brand-yellow-strong` is the selected tab pill; text uses only 12/14/16/18 px (24/32 for display numbers) and weights 400/500/700 (never 600 or 800); radii use `--radius-4/8/12/20`, not the DS `--radius-sm/md/lg`. Do not name a new app class `.eco-<name>` if the DS already has it (the app's own were renamed `.eco-me-avatar` / `.eco-me-greeting` for that reason). Service icons are the DS service-tile images in `public/ds/services/*.webp` (map in `shared/ds-service-icon.ts`; services without one keep a gradient glyph tile) and the wallet quick actions use `public/ds/icons/*.svg`, all exported from the DS bundle. Icons elsewhere are still lucide, not DS Hugeicons. The donut colours live in `SEGMENT_COLORS` in `bill-overview-screen.tsx`.

**Hóa đơn** (`components/parents/hoa-don/`) has no vanilla counterpart. It was built from design screenshots: list (entry screen), then Thông tin hóa đơn, then Xác nhận giao dịch, then Kết quả giao dịch (`bill-result-screen.tsx`, from a screenshot: "Trang chủ" calls `onGoHome`, "Giao dịch mới" returns to the Chưa thanh toán tab). The Đã thanh toán tab (not Chưa thanh toán) opens with a summary card "Tổng quan Hóa đơn" right under the tabs (year, "Tổng số tiền đã thanh toán: x đồng", no bill count on the list card or the overview; the overview shows two KPI boxes, "Tổng số tiền đã thanh toán" (left) and "Số hóa đơn" (right), the "Xem chi tiết ›" link sits inside the right box) whose "Xem chi tiết ›" opens `bill-overview-screen.tsx` (back returns to the list on the same tab; the overview student card has no "Đổi" button; its "Xem chi tiết ›" opens the Đã thanh toán tab scrolled so the "Hóa đơn đã thanh toán (n)" heading sits under the top bar; it has no "Chưa thanh toán" counter and no pay shortcut). The same card embeds the "Phân bổ danh mục" donut; the donut (chart, dotted straight leader lines to the % chips, callout, "Khác" sheet) is the shared `CategoryDonut` in `hoa-don/bill-category-donut.tsx`, also used by the overview. School-year helpers live in `hoa-don/bill-year.ts`. Tổng quan is derived entirely from `student.bills` at render time. The list has a **school-year filter** ("Năm học yyyy - yyyy ⌄" row with a notebook icon, `bill-year-row.tsx`, + bottom sheet; the overview has the same row and sheet (`YearFilter`), so the year can be changed there and the overview reloads for it, `HoaDonApp` state `year`, default = the school year of today, Aug→Jul; options from `availableYears`) under the student card: both tabs, the pay-flow select screen and the overview all load that year (`billsInYear`, `summarizeYear(student, now, year)`), and the overview's month chart ends at today for the current year and at July for a past one (`yearAnchor`). The overview's summary, donut and counts are scoped to the selected year; the total amount and the donut count paid items only, and "Số hóa đơn" counts bills with at least one paid item (fully or partly paid). `summarizeYear` still returns `unpaidCount` (BR-05: no paid item and at least one item still to pay) but no screen shows it. Donut categories are inferred from item names (`Học phí…`, `Tiền ăn…`, else the name itself); a category under 5% of the total folds into "Khác" (whose bottom sheet lists them), and at most 4 segments are shown. The month chart lists every month of the selected school year up to today (July for a past year), months without payments included (a 0 bar; tapping it says there is nothing paid); 5 are visible at a time and it scrolls sideways (`VISIBLE_MONTHS`), opening on the latest months, with a fixed amount axis on the left (0, half, top; the top is a round number from `niceCeil`) beside the scrolling bars, placed by billing period (`Bill.year`/`month`, not payment date). No month is preselected; tapping a bar lists that month's paid items, grouped into collapsible bills when the month has more than one. The Aug–Oct 2026 mock bills (5 in school year 2026-27: 3 fully paid, one of them without VAT, 1 partly paid, 1 unpaid) exist so it has data when opened in Oct 2026. "Xem hóa đơn ›" (shown only on fully paid bills with `hasVat`) opens `bill-invoice-pdf-screen.tsx`, an iframe on the static sample `web/public/invoices/<bill.id>.pdf` with back and download in the top bar; each `hasVat` bill needs its own PDF there. The warning row "Hóa đơn chưa được thanh toán xong" + "Thanh toán ngay" button on a partly paid bill (Đã thanh toán tab) opens the normal select screen (Thông tin hóa đơn) with every open item unchecked, same as the "Chưa thanh toán" tab's CTA. It uses its own `Student.bills` model (per-item `paid` flags), separate from `invoices`, which only drives Đóng học phí. A bill with some items paid appears in both tabs. Only `khoa` has bills, so the Home picker lists only students with `bills.length > 0`, and Home skips the picker when only one student qualifies. On Kết quả giao dịch the promo cards and "Chia sẻ" are inert. **DS look (2026-10-20):** the list, select, confirm and result screens use the DS classes directly (`eco-segment` tabs, `eco-billgrp` BillGroup for Chưa thanh toán, `eco-paidbill` PaidBillCard for Đã thanh toán, `eco-paycheck`, `eco-txn` TransactionSummary, `eco-paylist` / `eco-payopt`, `eco-actionfooter` / `eco-totalfoot`); shared bits are in `hoa-don/bill-ds.tsx` and the `.bill-ds*` rules at the end of `globals.css`. Paid amounts keep their leading minus (PRD).

**Student card** (`shared/header.tsx` `StudentHeader` and the header in `student-screen.tsx`) is deliberately compact: avatar, name and lớp only. The avatar is `shared/student-avatar.tsx` (`StudentAvatar`): an inline SVG boy or girl in school uniform chosen from `student.gender` ("Nữ" → girl), since the mock data has no photos; use it everywhere a student's picture is shown. Mã học sinh and trường are shown in the profile and in the lists/sheets, not here.

**Health card** (`student-screen.tsx`): BMI-for-age z-score bands drive the colour chips, the history sheet and the "Gợi ý cho ba mẹ" button, which now opens the `health-advice/` screen (Mục tiêu / Thói quen tabs, from the reference app) through the `healthadvice` intent; the older advice sheet (`Z_SCORE_ADVICE`, `zScoreTrendLine`, `ZScoreAdviceSheet`) is still in the file but no longer reachable. `healthHistory[0]` must stay equal to `heightCm`, `weightKg` and `zScore`, because the trend line compares entries `[0]` and `[1]`. The advice is intentionally generic and defers dosing and menus to a doctor, so keep it that way.

**Services built from the Confluence PRDs** (space EDUS, tree under pageId 92768750; there is no vanilla counterpart). Each is a folder in `components/parents/<feature>/` with an `index.tsx` app:
- `phieu-be-ngoan/` Phiếu bé ngoan (PH-17: school-year total, current-week card, history by month with week dots, detail with week tabs and teacher remark; data = `Student.goodBehavior.weeks`, seeded by `seedGoodBehavior`; it replaced the earlier vanilla-based "Phiếu của con / Tổng kết" tabs), `gallery/` Thư viện ảnh (PH-19: albums grid, day-grouped 3-column detail with lazy load, viewer with video/share; data `ALBUMS`), `feedback/` Góp ý (PH-20, laid out from the EDU-1498 wireframe PDF: list with search + status tabs and a fixed "Gửi góp ý mới" CTA; create with optional "Loại góp ý" (8 types, bottom sheet), ≤10 files with error tiles, confirm/discard popups; detail = info + conversation in one scroll with a sticky composer, "Mở lại" within 7 days of closing, unlimited re-opens, with a required "Lý do mở lại" saved as a reply (`kind: 'reopen'`); every reply shows its author — `FeedbackReply.sender` vs `CURRENT_PARENT` tells you / another guardian / school; data `FEEDBACKS`), `medicine/` Dặn thuốc (PH-13), `attendance/` Theo dõi điểm danh (PH-01, K12 two-session update; "Thống kê" tab), `menu/` Thực đơn (PH-08), `activity/` Hoạt động (PH-02, hearts synced list↔detail), `bulletin/` Bảng tin (PH-03), `diary/` Nhật ký chăm sóc (PH-12, Mầm non only), `chat/` Trao đổi (PH-14: pins max 3, long-press / right-click actions, 1,200-char limit, media needs text), `notifications/`.
- `spending/` Lịch sử chi tiêu and `timetable/` Thời khoá biểu were ported from the vanilla `SCREENS.spending/timetable` (the timetable PRD page is empty).
- Their content lives in `lib/school-data.ts` (menus, activities, bulletin, care diary, chat threads, albums, feedback; scoped by `student.school` / `className`) plus `Student.spending/timetable/attendance/medicine` in `lib/mock-data.ts`. Images are generated SVG data URIs (`scene()`, `pdfPage()`), so nothing is fetched.
- Shared building blocks: `shared/photo-viewer.tsx` (fullscreen, swipe, tap-to-zoom, download), `shared/media-grid.tsx` (1/2/3/4/5+ layouts), `shared/toast.tsx` + `shared/use-toast.ts`.

## Features and screens imported from the reference app (eduparents-new)

A teammate's fork (`~/Downloads/eduparents-new`, same DS) was merged in on 2026-10-20. Its CSS was extracted into `web/app/features-imported.css` (rules for classes our own CSS lacks, taken from its `globals.css` and `eco-ds-bundle.css`); do not edit that file by hand. The reference app uses its own 6-student roster and hard-coded per-student sample data, so wherever a screen shows a student header it was patched to read name / code / class / school from `MOCK_STUDENTS` (results, timetable, bulletin, spending, pickup).
- **New features**, each a folder under `components/parents/` with an `index.tsx`: `postpaid-fee/` (Học phí trả sau, intent `postpaid`, opens `FeeApp` after the landing), `pickup/` (Người đón trẻ, intent `pickup`, from the Học sinh settings sheet; data in `pickup-data.ts`, localStorage), `development/` (Tiến trình phát triển, Mầm non only, intent `development`, card on Học sinh), `survey/` (Khảo sát & Đóng góp card on Học sinh, intent `survey`, state in `lib/survey-storage.ts`), `health-advice/` (intent `healthadvice`), `topup-wallet/` and `transfer/` (wallet flows from ECO Me home). `student-settings-sheet.tsx` is the gear sheet on Học sinh (lock card toggle, Người đón trẻ, other rows are toasts).
- **Replaced by the reference versions** (DS-designed, with their own sample data): Bài tập (`homework/`, content modal, action sheet, success dialog), Đóng học phí (`fee/`: provider sheet, ECO School / TheSSC, invoice select / confirm, saved bills; needs `invoice/invoice-data.ts`), Lịch sử chi tiêu (`spending/`, rewired to `Student.spending`), Kết quả học tập (`results/`, Cấp 1 vs Cấp 2-3 by the class number), Thời khoá biểu, Bảng tin, Thực đơn (`menu/`, meals by day plus Minh bạch and GS1 traceability screens, wrapped by `MenuApp`). The older versions are in git history. Kept as ours: Điểm danh, Dặn thuốc, Hoạt động, Thư viện ảnh, Phiếu bé ngoan, Hóa đơn, Trao đổi, Nhật ký, Góp ý.
- Also taken: Báo vắng detail (`absence/absence-detail-screen.tsx`, opens from a list card, cancel a pending request), Liên kết học sinh redesign with QR scanner (`link-student/`), PWA (`app/manifest.ts`, `public/sw.js` (bypasses localhost), `components/pwa/pwa-installer.tsx`, icons) and a phone view (`app/pwa-mobile.css`: the iPhone frame is dropped on a real phone, or with `?mobile=1`; `?simulator=1` forces the frame). The status bar now floats over the screen; ECO Me home and the link intro are `.app-shell--fullbleed` (hero behind it). Every screen change scrolls `.screen-root` to the top.
- Not taken: care-log and invoice (we have Nhật ký chăm sóc and Hóa đơn), the reference's own Home, services list and Học sinh page.
